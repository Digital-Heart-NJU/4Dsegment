# 2026 November 23 Step 03 development log

Step 03 now defaults to automatic recovery across four approaches that preserve
the original vertex numbering and triangle connectivity. Official IPC Toolkit
recovery has passed a subject 23 ED RV test. Optional freezing and the automatic
sequence have passed synthetic geometry and orchestration tests; the latest
combined suite has 61 passing tests. A full patient run with the final automatic
mode and freezing remains the next manual validation task.

## Main changes

| Change | Final behavior | Main files |
| --- | --- | --- |
| Constrained optimization | Solves for clearance with displacement regularization, outward bounds, self-contact barriers, and continuous collision checks, preserving connectivity. | `model_vol_septum/constrained_epi.py` |
| Larger feasible directions | Corrects threatened patches using contact halfspaces and triangle area constraints over the movement path, allowing a fresh large proposed step at fallback entry. | `model_vol_septum/constrained_epi.py` |
| Official IPC Toolkit | Uses `ipctk==1.4.0` barrier energy, gradient, PSD Hessian, and TightInclusionCCD. The clearance objective and optimization orchestration remain project code. | `constrained_epi.py`, `environment/cme-dt-env.yml` |
| Constrained repair alternative | `normal` movement can hand over to constrained optimization from its last accepted coordinates. Original Step 02 connectivity and displacement reference remain in use. | `model_vol_septum/generate_open_volmesh.py` |
| PyMeshFix repair alternative | Repairs a disposable closed target and transfers nearby coordinate corrections back to the original mesh. Target triangles are discarded. | `model_vol_septum/pymeshfix_epi_repair.py` |
| Environment selection | Launcher selects the absolute project-local Conda prefix, avoiding a different named environment that lacks IPC. Import errors identify the interpreter and installation command. | `run_pipline.py`, `constrained_epi.py` |
| Minimum step override | Launcher accepts `--epi-min-accepted-step` and forwards it after configured defaults. It controls normal-mode acceptance and recovery triggering. | `run_pipline.py` |
| Optional freezing | `--epi-freeze-satisfied true` locks vertices already meeting clearance at optimizer or first local-repair entry. Local repair retains the locks when normal movement resumes. Default is false. | Both repair implementations and Step 03 |
| Automatic recovery | Tries normal+damping, normal+constrained, normal+PyMeshFix, then standalone constrained, independently for each chamber and frame. First validated saved result wins. | Step 03, launcher |
| Validation and reporting | Checks geometry before saving and after reload, including exact frozen coordinates. All requested Step 03 results remain staged until every surface passes. Logs include failed approaches and the selected approach. | Step 03, tests, `environment/README.md` |

## Freeze and automatic mode tests

- Freezing passed mixed-clearance sphere tests: locked coordinates stayed exact
  in Newton solves, direction correction, accepted movements, and saved files.
  Warm-start locks refer to repair-entry coordinates, not the original Step 02
  positions.
- Damping and PyMeshFix both passed a test that forces repair and then resumes
  normal movement, with frozen vertices remaining fixed.
- An octahedron with safe vertices but insufficient triangle-interior clearance
  failed as intended. A fully frozen triangle cannot be moved to repair that gap;
  the solver reports the conflict without releasing locks.
- Automatic mode passed tests for every possible successful position in the
  four-method order, fresh inputs and budgets after failure, independent chamber
  selection, and continuation after a missing-IPC error.
- Invalid solver geometry and corrupted saved geometry were rejected before the
  next approach ran. All-four failure stopped Step 04 and preserved previous
  outputs. Failure on ES also prevented publication of earlier staged ED meshes.
- A test forced all three normal approaches to fail, then used the real official
  IPC optimizer to deform synthetic surfaces successfully as the fourth attempt.
- The initial automatic-mode test fixtures failed saved `elemTag` checks because
  mocked successful meshes omitted the required labels. The fixtures were fixed
  to match Step 02 labels; the validation checks were retained.
- An exceptionally grazing IPC TightInclusionCCD test geometry had previously
  stalled. The regression fixture was changed to tilted sheets separated by
  0.001 mm; pathological grazing performance remains a consideration.

## Current behavior and commands

Automatic mode is the default in both the launcher and the Step 03 backend.
Each approach gets the configured outer iteration budget, default 600; a normal
approach shares that budget with its constrained fallback. Damping and PyMeshFix
retain a maximum of six local attempts per repair event.

```bash
# Full volumetric pipeline with the automatic sequence
python run_pipline.py --request volumetric --subject 23

# Same sequence with optional freezing
python run_pipline.py --request volumetric --subject 23 \
  --epi-clearance-method auto --epi-freeze-satisfied true

# Only Step 03, using saved Step 02 inputs
./cme-dt-env/bin/python -B -u model_vol_septum/generate_open_volmesh.py \
  --subject-dir data/subject_23 --frames ED,ES \
  --start-step 3 --stop-after 3 --overwrite \
  --epi-clearance-method auto --epi-min-accepted-step 0.01 \
  --epi-freeze-satisfied true

# Explicit single approach remains available
python run_pipline.py --request volumetric --subject 23 \
  --epi-clearance-method normal --epi-local-repair-method constrained \
  --epi-min-accepted-step 0.01

# Regression suite
env OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=4 \
  ./cme-dt-env/bin/python -B -m unittest discover -s model_vol_septum/tests -q
```

Freezing is selected once per optimizer or local-repair entry; vertices that
reach clearance later are not added to that attempt's fixed set. Automatic
retries select their own locks from their own entry state. Every approach must
preserve connectivity and pass whole-surface validation. SDF reconstruction
remains an explicit alternative and is outside the automatic sequence.

Runtime reports live under
`data/subject_<ID>/volmesh_pipline/step_03_move_RVepi/method_attempts/`.
The regular Step 03 summary also records `movement.automatic`, including the
selected approach and attempt history.
